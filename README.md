# food-stock-app

## 概要

食材の在庫管理を中心としたWebアプリケーションです。

食材の登録・編集・削除、在庫数量の更新、検索・絞り込みなど、日常的な在庫管理に必要な機能を段階的に実装します。

まずは、機械学習や外部APIを使用せず、在庫管理アプリとして単体で利用できる状態まで完成させます。

その後、レシートOCRによる在庫登録、在庫とレシピの照合、外部APIやAIを活用したレシピ提案などの機能を追加し、食材の管理から消費までを支援するアプリケーションへ発展させる予定です。

## 開発目的

日常生活では、現在の食材在庫を正確に把握できず、同じ食材を重複して購入したり、食材を使い切れずに廃棄してしまうことがあります。

本アプリでは、食材の在庫を簡単に登録・確認・更新できる仕組みを作ることで、以下の課題の解決を目指します。

* 食材の買い忘れ防止
* 食材の重複購入防止
* 消費期限切れによる食品ロスの削減
* 現在の在庫を活用した献立検討の支援

また、本プロジェクトを通して、以下の技術を用いたWebアプリケーション開発の流れを学ぶことも目的としています。

* FastAPI
* SQLAlchemy
* SQLite、PostgreSQL
* HTML、CSS、JavaScript
* データベース設計
* テスト
* Docker
* AWS
* Git、GitHub

## アプリケーションの方針

本アプリでは、以下の3つを中心に機能を実装します。

### 1. 在庫を管理する

* 食材を登録する
* 食材情報を編集・削除する
* 在庫数量を増減する
* 食材名で検索する
* カテゴリで絞り込む
* 在庫を並び替える
* 消費期限を確認する
* 購入単位の在庫内訳を確認する

### 2. 在庫を追加しやすくする

* 手動で食材を登録する
* 複数の食材をまとめて購入登録する
* レシートOCRの読み取り結果から食材を登録する
* 既存の食材がある場合は、在庫への追加または数量の変更を選択する

### 3. 在庫を活用する

* レシピを手動登録する
* 在庫から作成可能なレシピを検索する
* 不足している食材と数量を表示する
* 調理後に使用した食材を在庫から減らす
* 将来的に外部APIやAIを利用してレシピを提案する

## 主な機能

## Phase1：在庫管理アプリの完成

### Step1：食材在庫管理の基本機能

以下の機能を実装済みです。

* 食材一覧表示
* 食材新規登録
* 食材編集
* 食材削除
* 在庫数量の登録・更新
* 数量の0.5刻み入力
* カテゴリの入力候補表示
* 単位の入力候補表示
* 食材名検索
* 並び替え
* カテゴリによる絞り込み

### Step2：在庫数量の簡易操作

一覧画面から在庫数量を簡単に更新できるようにします。

* 一覧画面への「＋」「－」ボタン追加
* ボタン操作による数量の増減
* 在庫数量が0未満にならない制御
* 数量変更後の検索・絞り込み状態の維持
* 在庫数量が0の食材を分かりやすく表示
* 大きな数量変更は編集画面から実施

将来的には、購入画面または消費画面から複数の食材をまとめて増減できる機能を追加します。

### Step3：カテゴリ・単位の選択式入力

登録内容の表記揺れを防ぐため、カテゴリと単位を選択式に変更します。

カテゴリの候補例：

* 野菜
* 肉類
* 魚介類
* 卵・乳製品
* 主食
* 調味料
* 飲料
* 冷凍食品
* 加工食品
* その他

単位の候補例：

* 個
* g
* kg
* ml
* L
* 本
* 袋
* パック
* その他

「その他」を選択した場合は、任意の内容を入力できるようにします。

食材名からカテゴリや単位を自動入力する機能は必須機能とせず、必要に応じて食材名と入力候補の対応表を作成します。

自動入力されたカテゴリや単位は、利用者が変更できる仕様とします。

### Step4：重複食材の登録処理

同じ食材名がすでに登録されている場合に、重複を検知して確認画面を表示します。

例：

```text
「卵」はすでに登録されています。

現在の在庫：6個
今回の入力：4個

・在庫に追加して10個にする
・在庫を4個に変更する
・登録をキャンセルする
```

以下の処理を選択できるようにします。

* 既存の在庫数量に追加する
* 入力した数量に変更する
* 登録をキャンセルする

### Step5：検索・絞り込み・並び替えの改善

食材が増えた場合でも、目的の食材を見つけやすい画面にします。

* 食材名による部分一致検索
* カテゴリ絞り込みとの併用
* 食材名順の並び替え
* カテゴリ順の並び替え
* 在庫数量順の並び替え
* 検索条件・絞り込み条件の解除
* 数量変更後の検索条件維持

### Step6：入力チェックとエラー処理

誤った入力や操作が行われた場合でも、アプリケーションが停止しないようにします。

* 食材名の未入力チェック
* 数量への不正な文字入力の防止
* 負の数量の登録防止
* 存在しない食材IDへのアクセス処理
* 削除済み食材へのアクセス処理
* エラーメッセージの画面表示
* 登録・更新・削除完了メッセージの表示
* 削除前の確認表示

### Step7：画面と操作性の改善

日常的に利用しやすい画面へ整えます。

* ボタンや入力欄のデザイン統一
* 在庫数量が0の食材の強調表示
* データが0件の場合のメッセージ表示
* 数量と単位の表示形式統一
* 登録・編集後の画面遷移統一
* スマートフォン幅での最低限の表示確認
* 詳細画面の追加

### Step8：マイグレーションの導入

今後のテーブル変更を安全に管理するため、Alembicを導入します。

* Alembicの初期設定
* 現在のテーブル構成のマイグレーション管理
* カラム追加・変更手順の整備
* 既存データを保持した状態でのテーブル変更確認

消費期限や購入単位の在庫管理を実装する前に導入します。

### Step9：消費期限管理

食材の消費期限を確認できるようにします。

初期実装では、食材単位で在庫と消費期限をまとめて管理します。

同じ食材を追加した場合は、登録されている期限と新しい期限を比較し、期限が短い方を代表の消費期限として扱う予定です。

実装予定の機能：

* 消費期限の登録
* 消費期限の編集
* 消費期限が近い食材の強調表示
* 消費期限切れ食材の表示
* 消費期限順の並び替え
* 消費期限による絞り込み

### Step10：購入単位の在庫明細管理

将来的には、同じ食材でも購入日や消費期限ごとに在庫を分けて管理します。

例：

```text
卵：合計10個

内訳
・7月25日購入：6個
・7月29日購入：4個
```

一覧画面では食材ごとの合計数量を表示し、詳細画面では購入単位の内訳を表示します。

実装予定の機能：

* 購入単位の在庫登録
* 購入日の管理
* 購入単位ごとの消費期限管理
* 食材ごとの在庫合計表示
* 在庫詳細画面での内訳表示
* 消費期限が短い在庫から減らす処理

### Step11：複数食材の一括購入・一括消費

複数の食材をまとめて登録・更新できるようにします。

購入登録の例：

```text
卵　　　　10個
牛乳　　　1本
玉ねぎ　　3個
```

消費登録の例：

```text
卵　　　　2個
鶏肉　　　200g
玉ねぎ　　1個
```

実装予定の機能：

* 複数食材の一括購入
* 複数食材の一括消費
* 既存在庫への数量追加
* 在庫不足時の警告
* 登録内容の確認画面

### Step12：テストの追加

機能追加によって既存機能が壊れないように、自動テストを追加します。

* CRUD処理のテスト
* 在庫増減処理のテスト
* 在庫数量が0未満にならないことのテスト
* 重複登録処理のテスト
* 検索・絞り込み処理のテスト
* 入力チェックのテスト
* 消費期限処理のテスト
* 主要画面へのアクセス確認

テストには、主に `pytest` を使用する予定です。

### Step13：Phase1の仕上げ

在庫管理アプリとして公開できる状態へ整えます。

* READMEの更新
* 設計書と実装内容の整合性確認
* 画面画像の追加
* 操作方法の記載
* ディレクトリ構成の更新
* 不要なコードやファイルの整理
* `develop` ブランチから `main` ブランチへのマージ
* リリースタグの作成

ここまでを、在庫管理アプリとしてのPhase1完了とします。

## Phase2：レシピ管理・在庫活用

### レシピマスタ管理

利用者がレシピと必要な食材を手動で登録できるようにします。

例：

```text
レシピ名：親子丼

必要な食材
・卵　　　2個
・鶏肉　　200g
・玉ねぎ　1個
・米　　　300g
```

実装予定の機能：

* レシピ登録
* レシピ編集
* レシピ削除
* レシピ一覧表示
* レシピ詳細表示
* レシピごとの必要食材登録

### 在庫とレシピの照合

登録されたレシピと現在の在庫を比較します。

* 現在の在庫で作れるレシピの表示
* 不足している食材の表示
* 不足数量の計算
* 在庫の充足率による並び替え
* 調理後の在庫一括減算
* 調理履歴の保存

## Phase3：レシートOCR

レシート画像から商品名と購入数量を読み取り、在庫登録を支援します。

対象とする情報：

* 商品名
* 購入数量

価格、店舗名、支出金額などの家計簿機能は本アプリの対象外とします。

実装予定の流れ：

1. レシート画像をアップロードする
2. OCRで商品名と数量を読み取る
3. 読み取り結果を確認画面に表示する
4. 利用者が商品名、数量、単位を修正する
5. 確定した内容を在庫へ追加する

OCR結果は直接在庫へ登録せず、必ず利用者が確認・修正した後に反映します。

## Phase4：外部API・AI機能

在庫管理、レシピ管理、OCRなどの基本機能が完成した後に実装します。

実装候補：

* 外部レシピAPIからのレシピ取得
* 在庫を活用したレシピ提案
* 不足食材が少ないレシピの提案
* 消費期限が近い食材を優先したレシピ提案
* 利用履歴に基づくレシピ推薦
* 自然言語による献立相談
* 機械学習モデルを用いた推薦機能

AIや機械学習は、単純なルールやデータベース検索では実現しにくい機能に限定して使用します。

カテゴリや単位の自動入力など、対応表で十分に実現できる機能には、原則として機械学習を使用しません。

## Phase5：運用・クラウド対応

## ローカルでの起動方法

### 1. リポジトリをクローンする

```bash
git clone git@github.com:yuzuan419656/food-stock-app.git
cd food-stock-app
```

### 2. 仮想環境を作成する

```bash
python -m venv .venv
```

### 3. 仮想環境を有効化する

WSL / Linux / macOSの場合：

```bash
source .venv/bin/activate
```

Windows PowerShellの場合：

```powershell
.venv\Scripts\Activate.ps1
```

### 4. 必要なライブラリをインストールする

```bash
pip install -r requirements.txt
```

### 5. FastAPIアプリケーションを起動する

```bash
uvicorn app.main:app --reload
```

### 6. ブラウザで確認する

以下のURLにアクセスします。

```text
http://127.0.0.1:8000
```

食材在庫一覧画面が表示されれば、起動成功です。

FastAPIのAPIドキュメントを確認する場合は、以下のURLにアクセスします。

```text
http://127.0.0.1:8000/docs
```

## 開発方針

* 小さな単位で設計・実装・確認を行う
* まずは在庫管理アプリとして利用できる状態を完成させる
* 外部APIやAIに依存しない基本機能を先に実装する
* 実装難易度と利便性のバランスを考慮する
* 実装が難しい一方で利便性の向上が小さい機能は追加しない
* 将来の拡張を考慮したデータベース設計を行う
* 設計書と実装内容の整合性を保つ
* 1つのStepまたは機能ごとにfeatureブランチを作成する
* Pull Requestを通して変更内容を確認する
* 主要機能には自動テストを追加する

## ブランチ運用

本プロジェクトでは、以下のブランチ構成で開発します。

```text
main
 └── develop
      └── feature/*
```

各ブランチの役割は以下の通りです。

| ブランチ        | 役割                |
| ----------- | ----------------- |
| `main`      | 動作確認が完了した安定版      |
| `develop`   | 次回リリースに向けた開発内容の統合 |
| `feature/*` | 機能追加や修正を行う作業用ブランチ |

基本的な開発の流れ：

```text
Issue作成
↓
developからfeatureブランチを作成
↓
設計書の確認・更新
↓
実装
↓
動作確認・テスト
↓
commit
↓
push
↓
Pull Request作成
↓
developへマージ
↓
不要になったfeatureブランチを削除
↓
区切りのよいタイミングでmainへマージ
```
