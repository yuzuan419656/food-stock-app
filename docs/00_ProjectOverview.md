# Project Overview

## 1. プロジェクト概要

食材の在庫管理を中心としたWebアプリケーションを開発する。

まずは、食材の登録・編集・削除、在庫数量の更新、検索・絞り込み、消費期限管理など、日常的な在庫管理に必要な機能を実装する。

機械学習や外部APIに依存せず、在庫管理アプリとして単体で利用できる状態まで完成させた後、以下の機能を段階的に追加する。

* 手動登録したレシピと在庫の照合
* レシートOCRによる在庫登録支援
* 外部レシピAPIとの連携
* AI・機械学習を利用したレシピ提案

本アプリでは家計簿機能を実装対象とせず、食材の在庫管理と在庫の有効活用に機能を集中させる。

---

## 2. 開発背景・目的

日常生活では、現在保有している食材を正確に把握できず、以下のような問題が発生することがある。

* 同じ食材を重複して購入してしまう
* 必要な食材を買い忘れる
* 消費期限を把握できず、食材を廃棄してしまう
* 家にある食材を献立に活用できない

本プロジェクトでは、食材の在庫を簡単に登録・確認・更新できる仕組みを作ることで、買い忘れ、重複購入、食品ロスの削減を目指す。

また、在庫とレシピを照合する機能を追加し、現在保有している食材を献立に活用しやすくする。

本プロジェクトを通して、以下の技術を利用したWebアプリケーション開発の流れを習得することも目的とする。

* テスト

## 3. アプリケーションの基本方針

本アプリでは、以下の3つを中心に機能を構成する。

### 3.1 在庫を管理する

* 食材を登録する
* 食材情報を編集・削除する
* 在庫数量を増減する
* 食材名で検索する
* カテゴリで絞り込む
* 一覧を並び替える
* 消費期限を確認する
* 購入単位の在庫内訳を確認する

### 3.2 在庫を追加しやすくする

* 手動で食材を登録する
* 複数の食材をまとめて購入登録する
* レシートOCRの結果から食材を登録する
* 既存食材への数量追加または数量変更を選択する

### 3.3 在庫を活用する

* レシピを手動登録する
* 現在の在庫で作れるレシピを検索する
* 不足している食材と数量を確認する
* 調理後に使用した食材を在庫から減らす
* 将来的に外部APIやAIを利用してレシピを提案する

## 4. 開発目標

### Phase1：在庫管理アプリの完成

自分一人が日常的に利用できる、食材在庫管理アプリを完成させる。

主な実装対象は以下とする。

* 食材マスタ管理
* 食材の登録・編集・削除
* 在庫一覧表示
* 在庫数量の更新
* 一覧画面からの数量増減
* 食材名検索
* カテゴリ絞り込み
* 並び替え
* カテゴリと単位の選択式入力
* 重複食材登録時の確認
* 入力チェック
* エラー表示
* 消費期限管理
* 購入単位の在庫明細管理
* 複数食材の一括購入・一括消費
* 自動テスト

### Phase2：レシピ管理・在庫活用

利用者がレシピを手動登録し、現在の在庫と照合できるようにする。

主な実装対象は以下とする。

* レシピマスタ管理
* レシピの登録・編集・削除
* レシピごとの必要食材登録
* 現在の在庫で作れるレシピの表示
* 不足食材と不足数量の表示
* 調理後の在庫一括減算
* 調理履歴の保存

### Phase3：レシートOCR

レシート画像から商品名と購入数量を読み取り、在庫登録を支援する。

OCRの対象は以下とする。

* 商品名
* 購入数量

OCR結果は直接在庫へ登録せず、利用者が確認・修正した後に反映する。

価格、店舗名、支出額などの家計簿情報は対象外とする。

### Phase4：外部API・AI機能

基本機能の完成後に、外部APIやAIを利用した機能を追加する。

実装候補は以下とする。

* 外部レシピAPIからのレシピ取得
* 在庫を利用したレシピ提案
* 消費期限が近い食材を優先したレシピ提案
* 不足食材が少ないレシピの提案
* 利用履歴を利用したレシピ推薦
* 自然言語による献立相談
* 機械学習モデルを利用した推薦機能

AIや機械学習は、単純なルールやデータベース検索では実現しにくい機能に限定して使用する。

### Phase5：運用・クラウド対応

ローカル環境で基本機能を完成させた後、運用を想定した構成へ移行する。

* Docker対応
* SQLiteからPostgreSQLへの移行
* AWSへのデプロイ
* CI/CDの導入
* ログ管理
* 設定値と秘密情報の管理
* スマートフォン表示の改善
* ログイン機能
* マルチユーザー対応

ログイン機能とマルチユーザー対応は、単一ユーザー向けアプリとしての運用を確認した後に検討する。

## 8. システム概要

本システムは、ブラウザ上で利用するWebアプリケーションとして開発する。

ルートURL `/` には食材在庫一覧画面を表示し、利用者がアプリを開いた直後に現在の在庫状況を確認できるようにする。

利用者は、食材の登録・編集・削除と、在庫数量の更新を行う。

在庫情報はデータベースへ保存し、アプリケーションを終了した後も保持する。

初期段階では、食材ごとに数量をまとめて管理する。

将来的には、同じ食材を購入日や消費期限ごとの在庫明細として管理する。

例：

```text
卵：合計10個

内訳
・7月25日購入：6個
・7月29日購入：4個
```

一覧画面では食材ごとの合計数量を表示し、詳細画面では購入単位の内訳を表示する。

## 10. ブランチ運用

以下のブランチ構成を基本とする。

```text
main
 └── develop
      └── feature/*
```

各ブランチの役割は以下とする。

| ブランチ        | 役割                |
| ----------- | ----------------- |
| `main`      | 動作確認が完了した安定版      |
| `develop`   | 次回リリースに向けた開発内容の統合 |
| `feature/*` | 機能追加や修正を行う作業用ブランチ |

ドキュメントの軽微な修正など、GitHub上で直接変更する場合は、変更内容と影響範囲を確認したうえで対応する。

## 12. Design Principles

* 小さな単位で開発する
* まずは動くものを完成させる
* 在庫管理アプリとしての完成を優先する
* 外部APIやAIに依存しない基本機能を先に実装する
* 実装難易度と利便性のバランスを考慮する
* 実装が難しく、利便性の向上が小さい機能は追加しない
* 将来拡張できるデータ構造を意識する
* 設計書と実装内容の整合性を保つ
* シンプルで保守しやすい構成を維持する
* 主要機能には自動テストを追加する

## Project Vision

食材の在庫を分かりやすく管理し、重複購入や食品ロスを減らす。

さらに、現在保有している食材をレシピに活用することで、日々の食事管理を少し便利にする。
