# Project Overview

## 1. プロジェクト概要

食材の在庫管理を中心とした、単一ユーザー向けWebアプリケーションを開発する。

まずは、食材の登録・編集・削除、在庫数量の更新、検索・絞り込み・並び替え、重複登録時の確認、消費期限管理、買うものリストなど、日常的な在庫管理に必要な機能を完成させる。

在庫管理アプリとして単体で利用できる状態を完成させた後、レシピ管理、レシートOCR、外部API、AI・機械学習、クラウド運用を段階的に追加する。

本アプリでは家計簿機能を実装対象とせず、食材の在庫管理と在庫の有効活用に機能を集中させる。

---

## 2. 開発背景・目的

日常生活では、次のような問題が発生することがある。

- 同じ食材を重複して購入してしまう
- 必要な食材を買い忘れる
- 消費期限を把握できず、食材を廃棄してしまう
- 家にある食材を献立に活用できない

本プロジェクトでは、食材の在庫を簡単に登録・確認・更新できる仕組みを作り、買い忘れ、重複購入、食品ロスの削減を目指す。

また、個人開発を通して次の技術を利用したWebアプリケーション開発の流れを習得する。

- Python
- FastAPI
- SQLAlchemy
- Alembic
- SQLite
- PostgreSQL
- Jinja2
- HTML / CSS / JavaScript
- データベース設計
- 自動テスト
- Docker
- AWS
- Git / GitHub

## 3. アプリケーションの基本方針

### 3.1 在庫を管理する

- 食材を登録・編集・削除する
- 在庫数量を増減する
- 食材名で検索する
- カテゴリで絞り込む
- 一覧を並び替える
- 消費期限を一覧から直接入力・自動保存する
- 期限切れ・期限間近を分かりやすく表示する

### 3.2 買い忘れを防ぐ

- 在庫一覧から食材を選択して買うものリストへ追加する
- 同じ食材の重複追加を防ぐ
- 購入済み状態を管理する
- 不要な項目をリストから削除する
- 在庫が0になっただけでは自動追加しない

### 3.3 在庫を活用する

- レシピを手動登録する
- 現在の在庫で作れるレシピを確認する
- 不足している食材と数量を確認する
- 調理後に使用した食材を在庫から減らす
- 将来的に外部APIやAIを利用してレシピを提案する

## 4. 開発フェーズ

### Phase1：在庫管理アプリの完成

単一ユーザーがローカル環境で日常利用できる状態を完成させる。

実装対象：

- 食材マスタ管理
- 食材の登録・編集・削除
- 在庫一覧表示
- 在庫数量の更新
- 一覧画面からの数量増減
- 食材名検索
- カテゴリ絞り込み
- 並び替え
- カテゴリ・単位の選択式入力
- 重複食材登録時の確認
- 入力チェックとエラー表示
- 消費期限管理
- 買うものリスト
- 必要最小限の自動テスト

### Phase2：レシピ管理・在庫活用

- レシピの登録・編集・削除
- レシピごとの必要食材登録
- 現在の在庫で作れるレシピの表示
- 不足食材と不足数量の表示
- 調理後の在庫減算
- 調理履歴の保存

### Phase3：レシートOCR

- レシート画像のアップロード
- 商品名と購入数量の読み取り
- OCR結果の確認・修正
- 確定内容の在庫反映

価格、店舗名、支出額などの家計簿情報は対象外とする。

### Phase4：外部API・AI機能

- 外部レシピAPIからのレシピ取得
- 在庫を利用したレシピ提案
- 消費期限が近い食材を優先した提案
- 不足食材が少ないレシピの提案
- 利用履歴を利用した推薦
- 自然言語による献立相談

### Phase5：運用・クラウド対応

- Docker対応
- SQLiteからPostgreSQLへの移行
- AWSへのデプロイ
- CI/CD
- ログ管理
- 設定値・秘密情報の管理
- スマートフォン表示の改善
- ログイン機能
- マルチユーザー対応
