# Requirements

## はじめに

本書では、本システムが満たすべき要件を定義する。
各機能の詳細仕様については、「02_FunctionList.md」以降の設計書で定義する。

本システムは、レシートOCRを利用した食材管理・レシピ提案を行うWebアプリケーションである。

食材管理を効率化するとともに、在庫状況に応じたレシピを提案することで、献立決定の負担軽減と食品ロスの削減を支援することを目的とする。

---

# 1. システム要件

本システムは以下の要件を満たすものとする。

- Webブラウザから利用できること
- ローカル環境で動作すること
- 食材情報を永続化できること
- 手動で食材を登録できる
- 利用者が現在の在庫状況を確認できること
- レシピ実行後に在庫情報を更新できること

---

# 2. 機能要件

本システムは以下の機能を提供する。

## 2.1 食材マスタ管理

利用する食材の基本情報を管理できること。

### 要件

- 食材を登録できること
- 食材を編集できること
- 食材を削除できること
- 食材を検索できること

---

## 2.2 在庫管理

現在保有している食材の在庫を管理できること。

### 要件

- 食材ごとの在庫数を管理できること
- 在庫情報を更新できること
- 在庫一覧を確認できること
- 消費期限を管理できること（Phase2）

---

# 3. 非機能要件

## 開発環境

- Pythonを使用する
- FastAPIを使用する
- SQLiteを使用する（将来的にPostgreSQLへ移行可能な設計とする）
- SQLAlchemyを使用する
- GitHubでソースコードを管理する

## システム品質

- ブラウザ上で利用できること
- 拡張性を考慮した設計とする
- 保守しやすいディレクトリ構成とする
- 可読性を重視したコードを作成する

## 開発プロセス

- GitHub Flowを採用する
- GitHub Issueを作成してから開発を開始する
- Pull Requestを経由してdevelopブランチへマージする
- 各StepでDefinition of Doneを設定する

---

# 4. 制約事項

Phase1（MVP）では以下の機能は対象外とする。

- ログイン・ユーザー認証
- 複数ユーザー対応
- 家計簿機能
- AIによるレシピ推薦
- AWSへのデプロイ
- スマートフォンアプリ対応

---

# 5. 将来拡張

以下の機能については、将来的な実装を想定する。

- レシート画像からの読み取り
- 在庫状況に応じたレシピ提案
- PostgreSQLへの移行
- AWSへのデプロイ
- Docker対応
- Reactなどのフロントエンドフレームワーク導入
- マルチユーザー対応
- スマートフォンアプリ化
- 家計簿機能
- AIを利用したレシピ推薦
- 利用者の嗜好を考慮したレシピ提案

---

# 7. Definition of Done

Requirementsは以下を満たした時点で完成とする。

- システム要件が整理されている
- 機能要件が整理されている
- 非機能要件が整理されている
- 制約事項が整理されている
- 将来拡張が整理されている
- Project Overviewとの整合性が取れている
- 次工程（FunctionList）の作成に必要な情報が整理されている
