# Screen Design

## 1. 目的

本書では、食材在庫管理Webアプリケーションの画面設計を定義する。

画面一覧、画面遷移、各画面の役割、表示内容、入力項目、操作内容を整理し、ルーティングやテンプレートを実装する際の土台とする。

現時点では、Phase1で実装する在庫管理機能を中心に定義する。

Phase2以降の画面については、予定する画面と役割のみを記載し、実装前に詳細を更新する。

---

## 2. 前提・対象範囲

本アプリでは、起動直後に現在の在庫状況を確認できることを重視する。

そのため、専用のトップ画面は作成せず、ルートURL `/` に食材一覧画面を表示する。

Phase1では、主に以下の機能を対象とする。

* 食材一覧表示
* 食材新規登録
* 食材情報編集
* 食材削除
* 在庫数量更新
* 一覧画面からの在庫数量増減
* 食材名検索
* カテゴリ絞り込み
* 並び替え
* カテゴリ・単位の選択式入力
* 重複食材登録時の確認
* 入力チェック
* エラー表示
* 食材詳細表示
* 消費期限管理
* 購入単位の在庫明細表示
* 複数食材の一括購入
* 複数食材の一括消費

Phase1では、以下の機能を対象外とする。

* レシートOCR
* レシピマスタ
* レシピ検索
* 調理履歴
* 外部レシピAPI
* AIによるレシピ提案
* ログイン
* マルチユーザー
* AWSデプロイ

家計簿機能は、本アプリ全体の対象外とする。

## 5. 各画面詳細

## 5.1 S001 食材一覧画面

### 目的

登録済みの食材と現在の在庫数量を一覧で確認できるようにする。

アプリを開いた直後にこの画面を表示し、利用者がすぐに在庫状況を把握できるようにする。

### URL

```text
/
```

### 表示内容

| 項目        | 内容                  |
| --------- | ------------------- |
| アプリ名      | 食材在庫管理アプリであることを表示する |
| 食材名検索欄    | 食材名による部分一致検索を行う     |
| カテゴリフィルター | カテゴリによる絞り込みを行う      |
| 絞り込み解除    | カテゴリ絞り込みを解除する       |
| 食材名       | 登録済みの食材名            |
| カテゴリ      | 食材カテゴリ              |
| 在庫数量      | 現在の合計在庫数量           |
| 単位        | 個、g、ml、本などの基本単位     |
| 消費期限      | 代表となる消費期限           |
| 減算ボタン     | 在庫数量を1減らす           |
| 加算ボタン     | 在庫数量を1増やす           |
| 詳細ボタン     | 食材詳細画面へ移動する         |
| 編集ボタン     | 食材編集画面へ移動する         |
| 削除ボタン     | 食材削除確認画面へ移動する       |
| 新規登録ボタン   | 食材登録画面へ移動する         |
| 一括購入ボタン   | 一括購入画面へ移動する         |
| 一括消費ボタン   | 一括消費画面へ移動する         |

消費期限は、消費期限管理を実装する段階で追加する。

食材詳細ボタン、一括購入ボタン、一括消費ボタンは、それぞれの機能を実装する段階で追加する。

### 操作

| 操作       | 内容                 | 遷移先・結果                        |
| -------- | ------------------ | ----------------------------- |
| 食材名検索    | 入力した文字を含む食材だけを表示する | 同画面                           |
| カテゴリ絞り込み | 選択したカテゴリの食材だけを表示する | 同画面                           |
| 絞り込み解除   | カテゴリ絞り込みを解除する      | 同画面                           |
| 並び替え     | 指定した項目と順序で一覧を並び替える | 同画面                           |
| 減算       | 対象食材の在庫数量を1減らす     | 同画面                           |
| 加算       | 対象食材の在庫数量を1増やす     | 同画面                           |
| 新規登録     | 食材登録画面へ移動する        | `/ingredients/new`            |
| 詳細       | 食材詳細画面へ移動する        | `/ingredients/{id}`           |
| 編集       | 食材編集画面へ移動する        | `/ingredients/{id}/edit`      |
| 削除       | 食材削除確認画面へ移動する      | `/ingredients/{id}/delete`    |
| 一括購入     | 一括購入画面へ移動する        | `/inventory/purchases/new`    |
| 一括消費     | 一括消費画面へ移動する        | `/inventory/consumptions/new` |

### 数量増減の仕様

* 「＋」を1回押すと在庫数量を1増やす
* 「－」を1回押すと在庫数量を1減らす
* 在庫数量が0の場合は、それ以上減らせない
* 大きな数量変更や小数を含む変更は編集画面から行う
* 更新後も検索条件、カテゴリ絞り込み、並び替え条件を維持する

### 表示上のルール

* 在庫数量が0の食材は、文字、背景、ラベルなどで分かりやすく表示する
* 消費期限が近い食材は注意表示する
* 消費期限切れの食材は警告表示する
* データが0件の場合は、「登録されている食材はありません」などのメッセージを表示する
* 検索結果が0件の場合は、「条件に一致する食材はありません」などのメッセージを表示する

### 備考

専用のトップ画面は作成せず、この画面をアプリの入口とする。

購入単位の在庫明細を実装した後も、一覧画面では食材ごとの合計数量を表示する。

## 5.2 S002 食材登録画面

### 目的

新しい食材を登録し、在庫管理の対象に追加できるようにする。

### URL

```text
/ingredients/new
```

### 入力項目

| 項目      | 必須     | 内容                     |
| ------- | ------ | ---------------------- |
| 食材名     | 必須     | 登録する食材の名前              |
| カテゴリ    | 任意     | 候補から食材カテゴリを選択する        |
| その他カテゴリ | 条件付き必須 | カテゴリで「その他」を選択した場合に入力する |
| 基本単位    | 任意     | 候補から在庫管理の単位を選択する       |
| その他単位   | 条件付き必須 | 単位で「その他」を選択した場合に入力する   |
| 在庫数量    | 必須     | 現在保有している数量             |
| 購入日     | 任意     | 食材を購入した日               |
| 消費期限    | 任意     | 食材の消費期限                |

購入日と消費期限は、対応する機能を実装する段階で追加する。

### カテゴリ候補

* 野菜
* 肉類
* 魚介類
* 卵・乳製品
* 主食
* 調味料
* 飲料
* 冷凍食品
* 加工食品
* その他

### 単位候補

* 個
* g
* kg
* ml
* L
* 本
* 袋
* パック
* その他

### 表示内容

* 食材登録フォーム
* 登録ボタン
* キャンセルボタン
* 入力エラーメッセージ
* 食材名に応じたカテゴリ候補
* 食材名に応じた単位候補

### 操作

| 操作    | 内容                    | 遷移先 |
| ----- | --------------------- | --- |
| 食材名入力 | 対応するカテゴリ・単位候補があれば入力する | 同画面 |
| 登録    | 入力内容を検証して保存する         | `/` |
| キャンセル | 登録せず食材一覧画面へ戻る         | `/` |

### 重複食材の処理

同じ食材名がすでに登録されている場合は、即座に保存せず重複食材確認へ進む。

表示例：

```text
「卵」はすでに登録されています。

現在の在庫：6個
今回の入力：4個

・在庫に追加して10個にする
・在庫を4個に変更する
・登録をキャンセルする
```

### バリデーション

* 食材名は必須とする
* 食材名の前後の空白を除去する
* 在庫数量は必須とする
* 在庫数量は0以上とする
* 在庫数量は0.5刻みで入力できる
* カテゴリで「その他」を選択した場合はその他カテゴリを入力する
* 単位で「その他」を選択した場合はその他単位を入力する
* 入力エラー時は入力内容を可能な限り保持する

| 在庫数量    | 必須     | 現在の在庫数量                |
| 消費期限    | 任意     | 代表となる消費期限              |

* キャンセルボタン

### 操作

| 操作    | 内容            | 遷移先 |

## 5.5 S005 重複食材確認画面

### 目的

すでに登録されている食材と同じ名前の食材を登録しようとした場合に、在庫の扱いを利用者が選択できるようにする。

### URL

```text
/ingredients/duplicate
```

実装方法によっては専用URLを作成せず、食材登録画面内またはモーダルで表示する。

### 表示内容

| 項目     | 内容              |
| ------ | --------------- |
| 食材名    | 重複した食材名         |
| 現在の在庫  | 登録済みの在庫数量       |
| 今回の入力  | 新しく入力した数量       |
| 追加後の数量 | 現在数量と入力数量の合計    |
| 在庫に追加  | 現在数量へ入力数量を加える   |
| 数量を変更  | 現在数量を入力数量に置き換える |
| キャンセル  | 登録を中止する         |

### 操作

| 操作    | 内容              | 遷移先                |
| ----- | --------------- | ------------------ |
| 在庫に追加 | 既存在庫に今回の数量を加える  | `/`                |
| 数量を変更 | 既存在庫を今回の数量へ変更する | `/`                |
| キャンセル | 保存せず食材登録画面へ戻る   | `/ingredients/new` |

### 備考

「上書き」という表現は使用せず、「数量を変更する」と表示する。

使用した複数の食材を、1回の操作でまとめて在庫から減らせるようにする。

### URL

```text
/inventory/consumptions/new
```

| 項目   | 必須   | 内容           |
| ---- | ---- | ------------ |
| 食材   | 必須   | 登録済み食材から選択する |
| 消費数量 | 必須   | 在庫から減らす数量    |
| 単位   | 表示のみ | 対象食材の基本単位    |
| 現在庫  | 表示のみ | 現在の在庫数量      |

### 表示内容

* 食材選択欄
* 消費数量入力欄
* 入力行追加ボタン
* 入力行削除ボタン
* 現在の在庫数量
* 確認ボタン
* 消費登録ボタン
* キャンセルボタン
* 在庫不足の警告

### 操作

| 操作    | 内容               | 遷移先・結果     |
| ----- | ---------------- | ---------- |
| 行追加   | 消費する食材の入力欄を追加する  | 同画面        |
| 行削除   | 対象の入力欄を削除する      | 同画面        |
| 確認    | 消費内容と消費後の数量を表示する | 同画面または確認画面 |
| 消費登録  | 複数食材の在庫を減らす      | `/`        |
| キャンセル | 処理せず一覧へ戻る        | `/`        |

### バリデーション

* 消費数量は0より大きい値とする
* 現在の在庫を超える数量は登録できない
* 在庫不足の場合は対象食材と不足数量を表示する
* 購入単位の在庫明細がある場合は、消費期限が短い明細から減らす

## 5.9 S009 エラー画面

### 目的

存在しないデータへのアクセスや処理失敗が発生した場合に、利用者が状況を理解して次の操作を選べるようにする。

### 表示内容

* エラーの概要
* 発生した処理
* 利用者が行える対応
* 食材一覧へ戻るボタン

### 対象例

* 存在しない食材IDへアクセスした
* 削除済み食材へアクセスした
* データベース処理に失敗した
* 不正なURLへアクセスした
* 在庫数量を0未満にしようとした

## 10. 画面共通ルール

* ボタンの名称とデザインを統一する
* 登録、更新、削除の結果をメッセージで表示する
* エラー発生時は原因と対応方法を表示する
* 入力エラー時は入力済みの内容を可能な限り保持する
* 削除など元に戻しにくい操作は事前に確認する
* スマートフォン幅でも主要操作ができる表示とする
* 操作後は、利用者が次に確認すべき画面へ遷移する
* 検索、絞り込み、並び替え条件は可能な限り維持する
* 未実装の機能を画面上に表示する場合は、利用できないことが分かるようにする
