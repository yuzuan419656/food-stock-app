# Screen Design

## 1. 目的

本書では、Phase1（MVP）で実装する食材在庫管理Webアプリケーションの画面設計を定義する。

画面一覧、画面遷移、各画面の役割・表示内容・操作内容を整理し、実装時に必要なルーティングやテンプレート作成の土台とする。

---

## 2. 前提・対象範囲

本設計書では、Phase1で実装する画面のみを対象とする。

Phase1では、アプリを開いた直後に現在の在庫状況を確認できることを重視する。

そのため、専用のトップ画面は作成せず、ルートURL `/` に食材一覧画面を表示する。

Phase1で対象とする主な機能は以下とする。

* 食材の一覧表示
* 食材の新規登録
* 食材情報の編集
* 在庫数量の更新
* 食材の削除

対象外の機能は以下とする。

* レシートOCR
* レシピ検索
* レシピマスタ
* 調理履歴
* 家計簿
* 消費期限管理
* ログイン機能
* マルチユーザー対応
* AWSデプロイ

## 5. 各画面詳細

## 5.1 S001 食材一覧画面

### 目的

登録済みの食材と現在の在庫数量を一覧で確認できるようにする。

アプリを開いた直後にこの画面を表示することで、ユーザーがすぐに在庫状況を把握できるようにする。

### URL

`/`

### 表示内容

| 項目      | 内容                  |
| ------- | ------------------- |
| アプリ名    | 食材在庫管理アプリであることを表示する |
| 食材名     | 登録済みの食材名            |
| カテゴリ    | 食材カテゴリ              |
| 在庫数量    | 現在の在庫数量             |
| 単位      | g、個、本、mlなどの基本単位     |
| 新規登録ボタン | 食材登録画面へ移動する         |
| 編集ボタン   | 食材編集画面へ移動する         |
| 削除ボタン   | 食材削除確認画面へ移動する       |

### 操作

| 操作   | 内容               | 遷移先                        |
| ---- | ---------------- | -------------------------- |
| 新規登録 | 食材登録画面へ移動する      | `/ingredients/new`         |
| 編集   | 対象食材の編集画面へ移動する   | `/ingredients/{id}/edit`   |
| 削除   | 対象食材の削除確認画面へ移動する | `/ingredients/{id}/delete` |

### 備考

Phase1では、食材情報と在庫数量を同じ一覧画面で表示する。

専用のトップ画面は作成せず、この画面をアプリの入口とする。

---

## 5.2 S002 食材登録画面

### 目的

新しい食材を登録し、在庫管理の対象に追加できるようにする。

### URL

`/ingredients/new`

### 入力項目

| 項目   | 必須 | 内容           |
| ---- | -- | ------------ |
| 食材名  | 必須 | 登録する食材の名前    |
| カテゴリ | 任意 | 野菜、肉、魚、調味料など |
| 基本単位 | 任意 | g、個、本、mlなど   |
| 在庫数量 | 必須 | 現在保有している数量   |

### 表示内容

* 食材登録フォーム
* 登録ボタン
* キャンセルボタン

### 操作

| 操作    | 内容            | 遷移先 |
| ----- | ------------- | --- |
| 登録    | 入力内容を保存する     | `/` |
| キャンセル | 登録せず食材一覧画面へ戻る | `/` |

### バリデーション

* 食材名は必須とする
* 在庫数量は0以上とする
* 同じ食材名は登録できない

---

### 入力項目

| 項目   | 必須 | 内容         |
| ---- | -- | ---------- |
| 食材名  | 必須 | 食材の名前      |
| カテゴリ | 任意 | 食材カテゴリ     |
| 基本単位 | 任意 | g、個、本、mlなど |
| 在庫数量 | 必須 | 現在の在庫数量    |

### 表示内容

* 食材編集フォーム
* 更新ボタン
* キャンセルボタン

### 操作

| 操作    | 内容            | 遷移先 |
| ----- | ------------- | --- |
| 更新    | 入力内容を保存する     | `/` |
| キャンセル | 更新せず食材一覧画面へ戻る | `/` |

---

## 5.4 S004 食材削除確認画面

### 目的

食材を削除する前に、ユーザーが削除対象を確認できるようにする。

### URL

`/ingredients/{id}/delete`

### 表示内容

| 項目        | 内容              |
| --------- | --------------- |
| 食材名       | 削除対象の食材名        |
| カテゴリ      | 削除対象のカテゴリ       |
| 在庫数量      | 削除対象の現在数量       |
| 単位        | g、個、本、mlなどの基本単位 |
| 削除確認メッセージ | 削除してよいか確認する文章   |
| 削除ボタン     | 対象食材を削除する       |
| キャンセルボタン  | 削除せず一覧画面へ戻る     |

### 操作

| 操作    | 内容            | 遷移先 |
| ----- | ------------- | --- |
| 削除    | 対象食材を削除する     | `/` |
| キャンセル | 削除せず食材一覧画面へ戻る | `/` |

### 備考

誤操作を防ぐため、一覧画面から直接削除せず、削除確認画面を経由する。

## 6. CRUD機能との対応

| CRUD   | 機能          | 対応画面          |
| ------ | ----------- | ------------- |
| Create | 食材登録        | S002 食材登録画面   |
| Read   | 食材一覧表示      | S001 食材一覧画面   |
| Update | 食材編集・在庫数量更新 | S003 食材編集画面   |
| Delete | 食材削除        | S004 食材削除確認画面 |

## 7. 使用するデータ項目

Phase1の画面では、以下のデータ項目を使用する。

| 項目   | 対応テーブル                   | 内容         |
| ---- | ------------------------ | ---------- |
| 食材ID | ingredients.id           | 食材を識別するID  |
| 食材名  | ingredients.name         | 食材の名前      |
| カテゴリ | ingredients.category     | 食材カテゴリ     |
| 基本単位 | ingredients.default_unit | g、個、本などの単位 |
| 在庫数量 | inventories.quantity     | 現在の在庫数量    |

## 8. ルーティング案

実装時のルーティングは以下を想定する。

| HTTPメソッド | URL                        | 処理内容           |
| -------- | -------------------------- | -------------- |
| GET      | `/`                        | 食材一覧画面を表示する    |
| GET      | `/ingredients/new`         | 食材登録画面を表示する    |
| POST     | `/ingredients`             | 食材を登録する        |
| GET      | `/ingredients/{id}/edit`   | 食材編集画面を表示する    |
| POST     | `/ingredients/{id}/edit`   | 食材情報・在庫数量を更新する |
| GET      | `/ingredients/{id}/delete` | 食材削除確認画面を表示する  |
| POST     | `/ingredients/{id}/delete` | 食材を削除する        |

## 10. Definition of Done

本設計書は以下を満たした時点で完成とする。

* Phase1で必要な画面が定義されている
* 専用のトップ画面を作成しない方針が明記されている
* 画面一覧が整理されている
* 画面遷移図が作成されている
* 各画面のURLが定義されている
* 各画面の役割が記載されている
* 各画面の表示内容が整理されている
* 各画面の入力項目が定義されている
* 各画面のボタン・リンクが定義されている
* CRUD機能との対応関係が整理されている
* Project Overview、Requirements、DBDesignとの整合性が取れている
